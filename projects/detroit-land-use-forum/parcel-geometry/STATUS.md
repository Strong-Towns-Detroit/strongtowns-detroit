# Parcel geometry workstream status

Last updated: July 26, 2026

## Current forum artifact

The current exhibit is generated by `build_forum_asset.py` and written in
self-contained HTML, SVG, and PNG formats under `output/`.

Its public framing is:

- **Headline:** Detroit's lots don't fit Detroit's rules
- **Red:** Blocked by recorded dimensions
- **Navy:** Meets both minimums
- **Blue:** Incomplete data
- **Gray:** Outside analysis

The analysis is limited to parcels zoned R1–R6. Gray parcels can still be in
districts that permit residential uses; they are simply outside this analysis.

The legal minimum displayed is 5,000 square feet of lot area and 50 feet of lot
width. The screening calculation applies a uniform 1% measurement tolerance:
recorded area below 4,950 square feet or assessor frontage below 49.5 feet is
classified as blocked. Both valid measurements are required to classify a
parcel as meeting the minimums.

The exhibit includes this qualification:

> Unless a lot-of-record provision, combined zoning lot, adjustment, variance,
> or other exception applies, new development cannot proceed on these
> dimensions.

This is necessary because the assessor parcel is not always the legal zoning
lot, assessor frontage is only a proxy for ordinance lot width, and qualifying
pre-1968 lots may receive treatment directly under Detroit Code §50-13-21.

Current result after the uniform tolerance change:

- 331,307 R1–R6 parcels evaluated
- 291,819 blocked by recorded dimensions
- 39,488 meet both minimums
- 5,390 incomplete records, including missing zoning or measurement data
- 41,669 parcels outside the R1–R6 analysis

## Base Units geometry track

The companion pipeline is under `../base-units-geometry/`.

Official City Base Units snapshots have been downloaded:

- 486,540 address records
- 364,095 building records, whose status value is `Current`
- Base Units street centerlines

The fetcher was changed to:

- use POST requests, avoiding ArcGIS URL-length failures;
- cache pages and resume interrupted downloads;
- detect and refetch empty or truncated pages;
- retain only `objectid`, `parcel_id`, and `street_id` for addresses;
- stream consolidated GeoJSON instead of duplicating a full layer in memory.

### Frontage pilot

A fixed-seed 10,000-parcel pilot produced:

- 9,676 valid positive frontage comparisons
- median absolute difference: 0.13 feet
- 97.3% within 2 feet
- 97.7% within 5 feet
- 9,742 high-confidence geometry estimates
- 9,953 estimates using an address-to-street link

Zero assessor-frontage values are invalid measurements and have now been
excluded from validation statistics. Large disagreements remain useful audit
targets, especially consolidated, corner, curved, and irregular parcels.

The sample also produced 71 building-linked multi-parcel candidate sites. That
is not a citywide estimate.

### Current execution

A full-city `analyze` run was started after the pilot passed. It intersects
approximately 364,000 building footprints with the full parcel fabric and
estimates a street-facing edge for every parcel. Check the process/output before
starting another full run:

```bash
python projects/detroit-land-use-forum/base-units-geometry/analyze_base_units.py analyze
```

Successful completion writes `output/summary.json`,
`geometry_frontage_comparison.csv`, `geometry_frontage_sample.gpkg`,
`building_parcel_overlaps.csv`, and
`building_linked_candidate_sites.csv`.
